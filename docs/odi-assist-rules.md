## 一、体系总览：三层 × 双部门 × 四态

### 1.1 校验流水线（10 步，流程文档 §7.5 / 校验状态流 mermaid）

```
OCR/文本/版面解析 → 材料类型识别 → 部门归类(商务委/发改委/共用/无关)
→ 字段抽取 → 标准化 → 统一字段池写入 → 单材料校验
→ 部门内跨材料校验 → 跨业务核心字段校验(15组) → 结果聚合
```

触发守门：**版本哈希**。材料上传/替换/删除后重算 `material_version_hash`；与 `validated_version_hash` 相同则「开始校验」禁用（材料未变化不允许重复校验）。校验中锁定：上传、替换、删除、下载、生成、服务切换、对话输入。

### 1.2 结果模型（四态，注意"未触发"不是第四种结果）

| 状态 | 定义 | 计入汇总 |
|---|---|---|
| 通过 | 材料和字段已识别且规则成立 | ✅ |
| 不通过 | 条件完整但字段冲突/金额关系错误/股比计算错误/口径不成立 | ✅ |
| 缺失 | 材料未上传/无法识别/必填为空/置信度不足/缺币种单位汇率 | ✅ |
| 未触发 | 条件规则不适用或缺另一部门材料 —— **规则执行状态，不计入三态** | ❌（在规则详情中说明触发条件） |

汇总优先级：**不通过 > 缺失 > 通过**；汇总为不通过时仍显示缺失项数量和清单；风险提示不自动改变三态。正式版实现中 evaluation_status ∈ {evaluated, skipped, blocked, not_executed}，evaluated 时 outcome ∈ {passed, failed, missing}；`overall_outcome` 恒为 null（业务上不定义总判论，contracts.py:300）。

### 1.3 状态机（流程文档 §19）

- 文件状态：`uploading / upload_failed / pending_validation / validating / recognized / unrecognized / unrelated / invalidated`
- 校验任务：`no_file / pending / validating / completed / failed / outdated`
- 生成：`disabled / available / generating / generated / failed`

### 1.4 六条硬边界（客户评审口径，原文）

1. 填报演示只覆盖商务委，不提供文件上传。
2. 点击开始校验后才进行材料识别、部门归类、字段抽取和业务校验。
3. 材料版本未变化时，不允许重复校验。
4. 单条审核结果只有通过、不通过、缺失三类。
5. 跨业务只校验 15 组客观核心字段。
6. 发改委当前只提供材料校验，不提供材料生成。

非目标：不替代官方申报系统、不输出审批结论、不判印章签名真伪/签署权限/日期效力、不根据敏感词判备案核准结论、不自动补造事实、不做发改材料生成。

## 二、发改委通道：九族 152 条规则

### 2.0 引擎常量与全局语义（rules.py）

| 项 | 值 |
|---|---|
| 金额容差 | `TOLERANCE = 0.01`（万美元，十进制 Decimal，全程禁 float） |
| 金额相等 | `|a−b| ≤ 0.01` |
| 覆盖判定 | `actual + 0.01 ≥ expected`（允许 actual 比 expected 少 0.01） |
| 人民币折算 | `(cny余额/汇率).quantize(0.01)`；汇率=0 视为输入缺失（missing），不除零 |
| 出资方式枚举 | 货币/证券/实物/技术/知识产权/股权/债权/提供融资/提供担保/其他（10） |
| 资金来源枚举 | 境内自有/境内其他/境外自有/境外其他（4）；自有={境内自有,境外自有} |
| 归一化-企业名 | NFKC + 去空白（**不放宽逐字一致**，rules.py:68-77） |
| 归一化-项目名/地址/日期/经营范围 | NFKC + 去空白 + 去全部中英文标点（rules.py:80-85） |
| 计数合同 | 结果 checks 必须恰好 = implemented(82) ∪ blocked(3) = 85 条；scope_rule_count 恒 82、blocked 恒 3、catalogued_only 恒 67，偏差即抛 `NDRC_RULE_SET_INCOMPLETE`（contracts.py:408-427） |

## 三、商务委通道：分层校验 + 13 条即时校验

### 3.1 材料范围

**核心 4 类**（受支持可校验）：可行性报告（含"前期工作落实情况说明"变体）、商务委真实性承诺书、商务委备案申请表（境外投资备案表）、境外并购事项前期报告表（仅并购）。
**共用支持材料**：营业执照、公司章程、投资决策文件（股东会/董事会决议）、股权架构图、经审计财报、最近一期财报、资金来源证明、真实合规证明。
**识别但不支持**（`recognized_unsupported_materials`，可识别提示、不参与校验）：公司章程、投资决策文件、股权架构图、最近一期财报、投资环境报告、合规佐证（意向协议/租赁/设备采购/施工/薪资/政府许可/行情佐证）、增减资变更说明、并购佐证（并购协议/法律尽调/财务尽调/估值报告）。

### 3.2 校验分层（流程文档 §11）

1. **文件层**：可读、页面完整、类型可识别、商务委版本正确、主体可识别、多版本关系明确。
2. **单材料字段层**：必填、条件必填、格式、枚举值、内容充分性、表单内部金额与股比。
3. **主体与决策链（5 步）**：营业执照是主体基准 → 章程确定有权决策机构 → 决策文件中的决策机构与章程匹配 → 决议/承诺书/备案表/可研主体与投资事项一致 → 不一致显示证据位置**不自动选择**。
4. **项目场景**：投资方式/设立方式一致、承诺书版本与设立方式匹配（子公司/分公司不同模板）、境外企业中文名与外文名一致、投资国家一致、直接/最终目的地口径清晰、投资路径层级一致。
5. **金额币种股权**：注册资本<投资总额；中方+外方=投资总额；股比合计 100%；**股比与投资额占比基本一致**；出资币种折算合计=对应投资额；出资构成合计=中方投资额；资金证明金额与出资金额匹配。计算前必须识别数值、币种、单位、汇率。
6. **财务提示（不阻断）**：期末总负债/期末总资产 > 75% 负债率风险提示；未分配利润为负亏损提示；净利润为负盈利能力提示。
7. **前期工作报告**：新设查 16 项（投资主体概况/境外项目概况/股权结构/经营范围/经营期限/经营场所/经营模式/项目规划或建设方案/投资规模/行业属性/设施设备及人员投入/资金支出构成/投资必要性/实施进度/经济和社会效益/风险措施）；并购查 6 项（标的经营财务情况/合规性/合理性/必要性/风险防控）。

**形式审查边界**：决策文件和承诺书只识别签名/盖章**是否存在**，不判真伪/权限/日期效力。

**金额口径差异（重要）**：商务侧跨材料允许部分金额 ±5% 容差（仅作预警）；**发改侧不使用容差**（精确一致），见共性对照 R-004。商务侧不默认 1:7 汇率；注册资本≤投资总额仅大于时报错。

### 5.3 备案表口径要点（8 类表单模板提取）

**商务版（境外投资备案表，全表单位万美元）**：基本事由一句话（主体+国家+方式+目标企业）；投资路径仅第一层级可多行；最终目的地三段式（国家/省州/城市）；境外企业中/外文名成对；股权结构多股东；设立方式三选一（新设/并购/变更）；行业下拉+两个敏感勾选；注册资本含中外方占比；投资规模固定句式（总额折人民币+中方折人民币+外方折人民币+汇率）；中方出资币种/金额可多组；**中方投资构成境内 5+3 分项**（现金出资是合计项，其中含自有资金+银行贷款；实物/无形资产/股权/其他）**境外 3 分项**（自有/银行贷款含内保外贷外保外贷/其他）；项目简况/项目意义有括号内容要求（并购类简况须含目标公司经营财务状况及收购方案）。

**发改版（境外投资项目备案表，19 项）**：项目名称口径（主体+目的地+内容关键词）；投资主体 7 要素以营业执照为准 + 近两年信用情况**逐层穿透至最终实控人** + 财务四科目（万元人民币）；受控境外企业 5 要素；投资地点三档（直接=第一层级企业所在地/最终=最终层级或被收购企业注册地/其他有关）；行业下拉跨行业取占比最大（**敏感行业不论占比均应核准而非备案**）；投资方式四选一（新建/并购/增资/其他）；背景=必要性+前期工作+审批情况；主要内容和规模分新建类/并购类两套口径（并购=收购标的情况+收购方案，含估值方法和收购前后股权架构图）；总投资/中方投资额三件套（万美元金额+汇率+实际币种金额）；**中方投资额构成明细**（编号/企业/出资方式10选/来源4选/金额万美元折算/备注；同一企业不同方式来源分行；其他须备注）；用途说明；其他企业出资；风险应对；国家利益安全影响（含 74 号文禁止类/联合国制裁决议等 6 要素）；下一步计划；政府协助；需说明事项；附件清单 7 项；联系人 7 项。

**单位口径是第一风险点**：商务备案表全表万美元；发改备案表主体与财务=万元人民币、投资额=万美元、注册资本（主体）=万元人民币 vs（境外目标企业）视商务口径万美元。

## 七、引擎实现语义（POC 移植时的设计约束）

1. **fail-closed**：全链路无猜测回填。识别不出→UNSUPPORTED_MATERIAL_CONTENT；证据定位不到行→EVIDENCE_BOUNDARY_NOT_FOUND（不退回整页邻域）；JSON 禁重复键/浮点/NaN；金额全程 Decimal 定点字符串。
2. **冲突即失败**：构成行或融资构成携带多候选（表内金额 vs 备注折算重算值不一致）时直接 FIELD_CONFLICT，**不选边**。
3. **单字段降级链**：严格模板抽取失败→逐字段标签抽取降级；承诺书无标签降级（只有候选法：候选唯一→extracted、多值→ambiguous+conflicts、全空→missing）。
4. **多主体绑定**：USCC 优先、规范全称其次；同主体同 SHA 幂等去重；无法绑定→SUBJECT_UNBOUND 不阻断；备案表拆单元格致 OCR 顺序错乱时，仅当代码数=出资表唯一主体数才按原序补齐，否则不猜。
5. **统一字段池**：字段保存原始值/标准化值/口径/来源文件/证据位置/部门/置信度/材料版本/状态/人工确认/派生来源；**同一字段多值全部保留不自动覆盖**。字段状态（≠审核结果）：identified/missing/conflict/low_confidence/not_applicable/confirmed。
6. **来源优先级**：主体信息←营业执照；商务事实←可研+正式材料；表单值←各自备案表；财务←审计财报；资金←资金文件。
7. **消息文案模板**（message_catalog）：字段缺失=`未识别到【字段名称】，该项校验结果为缺失。`；材料缺失=`未上传或未识别到【材料名称】，相关审核暂无法完成。`
8. **生成边界**：不编造名称/金额/股比/目的地；缺失留空；冲突不自动选择；不生成签名签章；发改委不生成材料（硬边界⑥）。
