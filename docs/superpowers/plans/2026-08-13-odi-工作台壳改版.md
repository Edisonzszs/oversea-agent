# ODI 工作台壳改版 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: 用 superpowers:subagent-driven-development 或 inline 执行。本改版**保留**已完成的 P0+P1 填报演示流程(7 轮向导+生成+伴填),只在其前面加"工作台列表 + 项目概览 hub"两层壳。

## 背景 / 为什么要改

P0+P1 已完成:ODI 入口(OdiEntry)→ 新建弹窗 → 直接进 `OdiGuideDetailPage`(7 轮向导)。

**问题**:把"工作台壳"跳过了。用户要的层级是:
```
ODI 工作台 (列表)  →  项目工作台 (概览 hub)  →  [进入填报演示] / [进入申报助办]  →  流程引导(被触发才出现)
```
即:工作台(沿用旧平台 `OdiProjectListPage` 样式)是壳;填报演示(我的 7 轮向导)和申报助办(上传校验生成,P2)是从概览 hub **触发**的子流程。

**本改版只动"壳 + 路由"**,不动已建的字段池/向导/生成/伴填逻辑。

## Goal

在 `odi/` 模块新增工作台列表页 + 项目概览 hub 页,把现有向导降级为"从概览触发的子流程",视觉对齐旧 ODI 平台。

## Architecture

mode `"odi"` 内部新增 `odiView` 状态机(替换原来仅靠 `activeOdiId` 是否为空判断):
- `odiView="workbench"` → `OdiWorkbench`(列表,landing)
- `odiView="overview"` + activeOdiId → `OdiProjectOverview`(概览 hub)
- `odiView="guide"` + activeOdiId → `OdiGuideDetailPage`(现有向导,从概览触发)
- `odiView="assist"` + activeOdiId → `OdiAssistPlaceholder`(P2 占位)

数据模型 **不大改**:保留 `service: "guide"|"assist"` 作卡片主题/统计用;概览 hub 无论 service 都展示 [进入填报演示] + [进入申报助办] 两个入口(用户可进任一流程),符合结构 1。

## Tech Stack

React 18 + TS + Vite 6(esbuild transpile-only,**无 tsconfig**)。100% 内联样式。vitest 测试门 + /browse 端到端验收。npm 必须用 npmmirror 镜像。

## Global Constraints

- 不破坏现有 53 个测试;新增 smoke 测试覆盖新组件渲染。
- 不改 `odi/field/*`、`odi/copilot/*`、`odi/doc/*`、`odi/data/odiScenePresets.ts`(已稳定的填报演示内核)。
